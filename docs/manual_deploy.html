Manual Oficial de Deploy de Aplicações Web

Guia completo de implantação, infraestrutura e publicação em produção das aplicações web corporativas geradas visualmente pelo Vox Studio RAD.

Tecnologia Frontend HTML5 + CSS Delphi RAD + JS
Backend REST Node.js (Built-in HTTP/REST)
Banco de Dados SQLite (Portátil) / Firebird / Postgres
Porta Padrão 5000 (Configurável via PORT)
Autonomia 100% Independente da IDE

1 Anatomia da Pasta dist/web-app/

Quando você clica em "Compilar Aplicação Web" ou executa o projeto com o alvo Web Browser selecionado, a IDE gera uma pasta completamente autônoma em:

📁 d:\Projetos AntiGravity\VOXIDERAD\dist\web-app\

Arquivo / Diretório Tipo Responsabilidade em Produção
index.html HTML5 Interface gráfica completa: menus, painéis, DBGrid, botões e modais gerados a partir do formulário RAD.
css/app.css CSS3 Design system responsivo com layout Delphi Moderno, grid de dados, tipografia e temas.
js/app.js JavaScript Lógica da aplicação web: manipuladores de eventos (OnClick, OnChange), validações e binding.
js/erp_engine.js JavaScript Motor de cálculo de impostos, regras comerciais, estoque e emissão de cupom fiscal/relatórios (quando aplicável).
server.js Node.js Servidor web e API REST de alta performance, responsável por responder requisições e consultar o banco de dados.
clientes_vox.db SQLite Banco de dados relacional local, com tabelas de clientes, produtos, notas fiscais e vendas.
package.json Manifesto Declaração do projeto Node.js com script de inicialização padrão (npm start).
Dockerfile Docker Instruções prontas para empacotar a aplicação em uma imagem de container Docker ultra-leve (Alpine Linux).
docker-compose.yml Orquestração Arquivo para subir a aplicação em produção com um único comando e persistência de volume do banco.
💡
Aplicação 100% Desacoplada da IDE Para implantar o sistema no cliente ou na nuvem, você não precisa copiar toda a IDE Vox Studio RAD. Basta copiar apenas a pasta dist/web-app/! Ela contém tudo o que é necessário para rodar.

2 Arquitetura do Backend REST Integrado

O arquivo server.js gerado na raiz da pasta dist/web-app/ foi desenvolvido para ter zero dependências externas complexas. Ele utiliza exclusivamente as APIs nativas do Node.js:

⚡
Node.js HTTP & SQLite
Usa o módulo nativo http e o driver embutido node:sqlite (disponível a partir do Node.js v22), proporcionando velocidade máxima de I/O sem sobrecarga.
🔄
Endpoints REST Padronizados
Fornece rotas CRUD prontas para qualquer banco: GET /api/data, POST /api/data, PUT /api/data/:id, DELETE /api/data/:id e POST /api/db/query.
🌐
Suporte a Nuvem Dinâmica
Lê automaticamente a porta definida pelo provedor via process.env.PORT e o caminho do banco via process.env.DB_PATH.

3 Deploy em Servidor Local ou Intranet com PM2

Este é o método mais recomendado para redes internas de empresas, escritórios e redes locais (Windows Server ou Linux). O PM2 mantém a aplicação viva 24/7 e gerencia reinicializações automáticas.

📋
Passo 1: Instalar o Node.js no Servidor Baixe e instale o Node.js (versão LTS recomendada: v20 ou v22+) no servidor a partir de nodejs.org.
📋
Passo 2: Copiar os Arquivos da Aplicação Copie todo o conteúdo da pasta dist/web-app para o diretório de destino do servidor (exemplo: C:\Sistemas\MeuERP no Windows ou /var/www/meu-erp no Linux).
Comandos no Terminal do Servidor (PowerShell ou Bash) Terminal 
# 1. Instalar o PM2 globalmente na máquina
npm install -g pm2

# 2. Entrar na pasta onde os arquivos foram copiados
cd C:\Sistemas\MeuERP    # (ou: cd /var/www/meu-erp no Linux)

# 3. Iniciar o servidor da aplicação com o nome "vox-erp"
pm2 start server.js --name "vox-erp"

# 4. Salvar o estado da lista de processos para inicialização automática no boot
pm2 save

# 5. Gerar e ativar o serviço de inicialização no boot do sistema operacional
pm2 startup
✔
Acesso na Rede Local Após iniciar, qualquer computador conectado na rede local (Wi-Fi ou cabo) poderá abrir o sistema digitando no navegador:
http://<IP_DO_SERVIDOR>:5000 (ex: http://192.168.1.100:5000).

Comandos Úteis de Manutenção do PM2

Comandos de Monitoramento CLI 
pm2 status             # Ver status de execução e uso de memória/CPU
pm2 logs vox-erp       # Ver logs de acessos e erros em tempo real
pm2 restart vox-erp    # Reiniciar a aplicação após atualizar arquivos
pm2 stop vox-erp       # Parar a aplicação temporariamente

4 Deploy com Contêineres Docker (Zero Configuração)

Para quem utiliza Docker ou Kubernetes na empresa ou na nuvem, a pasta dist/web-app/ já é gerada com o Dockerfile e o docker-compose.yml configurados!

Subir o Contêiner com Docker Compose Docker 
# Entrar na pasta da aplicação
cd dist/web-app

# Construir e iniciar o container em segundo plano (detached mode)
docker compose up -d --build
🐳
Persistência de Dados Garantida O arquivo docker-compose.yml mapeia o volume ./clientes_vox.db:/app/clientes_vox.db, garantindo que todas as vendas, cadastros e atualizações feitas na base SQLite permaneçam salvas no disco mesmo se o contêiner for reiniciado ou recriado!

Parar ou Reiniciar o Container Docker:

Comandos Docker Docker CLI 
docker compose logs -f    # Acompanhar logs do contêiner
docker compose restart    # Reiniciar o serviço
docker compose down       # Parar e remover o contêiner

5 Deploy em Servidor Cloud VPS (Ubuntu + Nginx + SSL Grátis)

Este cenário é ideal para colocar o sistema na internet com um domínio próprio (ex: https://sistema.minhaempresa.com.br) protegido por HTTPS e certificado digital Let's Encrypt.

1
Preparar o Servidor Linux (Ubuntu 22.04 ou 24.04 LTS) Conecte-se ao seu servidor via SSH e instale os pacotes necessários:
Instalação de Pacotes no Ubuntu Bash 
sudo apt update && sudo apt upgrade -y
sudo apt install -y nodejs npm nginx certbot python3-certbot-nginx
sudo npm install -g pm2
2
Copiar a Aplicação e Iniciar com PM2
Configuração do Diretório /var/www Bash 
# Criar a pasta de destino
sudo mkdir -p /var/www/vox-erp
sudo chown -R $USER:$USER /var/www/vox-erp

# (Copie os arquivos de dist/web-app para /var/www/vox-erp via SCP ou SFTP)

# Iniciar com PM2
cd /var/www/vox-erp
pm2 start server.js --name "vox-erp"
pm2 save
pm2 startup
3
Configurar o Nginx como Proxy Reverso Crie o arquivo de configuração do site no Nginx:
Arquivo /etc/nginx/sites-available/vox-erp Nginx Config 
server {
    listen 80;
    server_name sistema.minhaempresa.com.br;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
Ativar a Configuração no Nginx Bash 
sudo ln -s /etc/nginx/sites-available/vox-erp /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
🔒
Passo 4: Gerar Certificado SSL Gratuito (HTTPS) Execute o comando do Certbot para que ele configure o certificado com renovação automática:

sudo certbot --nginx -d sistema.minhaempresa.com.br

Seu sistema estará no ar com HTTPS e cadeado de segurança verde!

6 Deploy em Nuvem PaaS (Render, Railway, Fly.io)

Se você prefere não gerenciar servidores Linux, atualizar pacotes ou configurar Nginx manualmente, você pode utilizar plataformas modernas de PaaS (Platform as a Service):

Render (render.com)
Permite subir Web Services Node.js com plano gratuito ou planos a partir de $7/mês com certificado SSL automático e deploys via GitHub.
Railway (railway.app)
Detecta automaticamente o package.json ou Dockerfile e cria uma URL pública HTTPS em menos de 1 minuto.
Fly.io (fly.io)
Excelente para rodar aplicações Node.js e Docker próximas aos usuários com suporte a volumes persistentes para bancos SQLite.
🚀
Como Fazer:
  1. Crie um repositório privado no GitHub e envie os arquivos da pasta dist/web-app;
  2. Acesse o Render.com ou Railway.app;
  3. Clique em "New Web Service" e conecte seu repositório;
  4. Defina o comando de build como vazio (não precisa) e o comando de start como: node server.js;
  5. Clique em Deploy! O serviço fornecerá uma URL pública como https://vox-erp.onrender.com.

7 Deploy como Serviço Nativo do Windows (Windows Service)

Em servidores Windows Server de empresas, muitas vezes é necessário que a aplicação web inicie assim que o servidor ligar, mesmo sem nenhum usuário fazer login na Área de Trabalho.

A ferramenta recomendada é o NSSM (Non-Sucking Service Manager):

Criando o Serviço Windows com NSSM (Prompt de Comando como Administrador) CMD (Admin) 
# 1. Baixar o NSSM (nssm.cc) e colocar na pasta C:\Sistemas\
# 2. Instalar o serviço:
nssm install VoxWebService "C:\Program Files\nodejs\node.exe" "C:\Sistemas\MeuERP\server.js"

# 3. Definir a pasta de trabalho da aplicação:
nssm set VoxWebService AppDirectory "C:\Sistemas\MeuERP"

# 4. Iniciar o serviço:
nssm start VoxWebService
✔
O serviço VoxWebService agora aparecerá na lista de Serviços do Windows (services.msc) com tipo de inicialização "Automático". Se a máquina reiniciar por falta de energia ou manutenção, o sistema web voltará sozinho!

8 Configurações de Segurança, Firewall & Backup

1. Liberar a Porta no Firewall do Windows

Para que os computadores clientes consigam acessar o servidor na rede local, a porta 5000 deve ser liberada nas regras de entrada do Firewall:

Liberar Porta via PowerShell (Executar como Administrador) PowerShell 
New-NetFirewallRule -DisplayName "Vox Studio Web App (Porta 5000)" -Direction Inbound -LocalPort 5000 -Protocol TCP -Action Allow

2. Rotina de Backup Automático do Banco SQLite

O SQLite permite fazer cópias quentes (hot backups) sem travar a aplicação em execução:

Comando de Backup Seguro do SQLite PowerShell / Bash 
# No Windows:
copy clientes_vox.db "C:\Backups\clientes_vox_%date:~-4,4%%date:~-7,2%%date:~-10,2%.db"

# No Linux (com script cron diário):
cp /var/www/vox-erp/clientes_vox.db /backups/clientes_vox_$(date +%Y%m%d).db

9 Diagnóstico & Resolução de Problemas no Deploy

Problema / Erro Causa Raiz Solução Recomendada
Error: listen EADDRINUSE: address already in use :::5000 Já existe outro processo utilizando a porta 5000 na máquina. Mate o processo anterior com pm2 stop all ou altere a porta rodando com PORT=8080 node server.js.
Outros computadores na rede não abrem a página. O Firewall do Windows ou Linux está bloqueando conexões externas na porta 5000. Crie uma regra de entrada liberando a porta 5000 no Firewall ou use Nginx na porta 80/443.
Erro de permissão no arquivo SQLite (EPERM ou read-only database). O usuário do Linux/Windows que executa o Node.js não tem permissão de escrita no arquivo .db. No Linux execute chmod 664 clientes_vox.db e no Windows garanta controle total para o usuário do serviço.
Ao atualizar arquivos a tela continua antiga. O navegador do cliente manteve arquivos em cache estático local. Oriente os usuários a pressionarem Ctrl + F5 no navegador após uma atualização de versão.
