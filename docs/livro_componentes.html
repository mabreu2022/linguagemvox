Prefácio: O Poder do Desenvolvimento Rápido de Aplicações

O paradigma **RAD (Rapid Application Development)** revolucionou a engenharia de software na década de 1990 com a introdução da biblioteca VCL (Visual Component Library) no Borland Delphi. O princípio fundamental era simples, porém transformador: softwares robustos devem ser compostos por blocos de construção reutilizáveis, modulares e configuráveis visualmente em tempo de design.

A **Linguagem Vox** resgata essa produtividade lendária e a une às demandas dos ambientes modernos: execução em navegadores Web sem perda de desempenho, forte tipagem estática, persistência estruturada em arquivos de formulário (.vxf) e distribuição organizada de componentes em bibliotecas de design (.vdpk).

Capítulo 1

A Filosofia de Componentes no Vox e o Paralelo com a VCL do Delphi

No Delphi, a espinha dorsal de todo o ecossistema é o TComponent, classe ancestral contida na unit System.Classes. Qualquer entidade que herde de TComponent herda automaticamente duas capacidades fundamentais:

  1. Capacidade de Pertencimento (Owner Model): Um componente gerencia a destruição de seus filhos (gestão hierárquica de memória e recursos).
  2. Capacidade de Streaming: As propriedades publicadas no bloco published são automaticamente lidas e gravadas em arquivos de recursos (os famosos formulários .dfm).

No Vox, o conceito é rigorosamente preservado sob a arquitetura Vox RAD Architecture (VRA). A classe ancestral vox_Component fornece a interface de streaming com os formulários .vxf (Vox Visual Form), enquanto o subsistema de reflexão da IDE expõe dinamicamente todas as variáveis declaradas com pub let mut no Object Inspector.

Tabela de Correspondência Arquitetural: Delphi VCL vs. Vox RAD

Conceito Delphi (VCL / FireDAC) Equivalente na Linguagem Vox Função e Responsabilidade
TComponent classe vox_Component Base universal de todos os componentes (visuais ou serviços em background).
TControl / TWinControl classe vox_VisualControl Controle com coordenadas físicas (left, top, width, height) e renderização visual.
TDataModule classe vox_DataModule Módulo não-visual que abriga componentes de conexão, tabelas e regras de negócio.
TFDConnection (FireDAC) vox_Connection Conexão direta a Firebird, MySQL, PostgreSQL, SQLite, com porta TCP e DLL de cliente (VendorLib).
Arquivo de Form .dfm Arquivo de Form .vxf Formato de streaming que armazena a disposição geométrica e valores iniciais das propriedades.
Pacote de Design .dpk Pacote de Design .vdpk Arquivo de manifesto e código do pacote compilável e instalável na IDE.
procedure Register; procedimento Register() Ponto de entrada oficial invocado pela IDE para registrar o componente na Tool Palette.
Capítulo 2

Anatomia de um Componente Vox

Um componente bem arquitetado na linguagem Vox possui quatro blocos essenciais:

  1. Declaração de Herança: Especifica a classe base (ex: vox_Panel, vox_VisualControl ou vox_Component).
  2. Propriedades Publicadas (Published): Declaradas com o modificador pub let mut. Elas aparecem instantaneamente no Object Inspector da IDE.
  3. Método Construtor / Inicializador (Inicializar): Configura dimensões padrão, cores e valores iniciais.
  4. Método de Renderização (Renderizar): Retorna a marcação estruturada que define a aparência do controle tanto no designer quanto no navegador do cliente final.

Código Modelo: Anatomia Completa

// Definição da classe do componente
classe vox_CardMetrica herda vox_Panel {
    // 1. Propriedades Inspecionáveis no Object Inspector
    pub let mut Titulo: string;
    pub let mut Valor: string;
    pub let mut VariacaoPercentual: f32;
    pub let mut CorDestaque: string;
    pub let mut ExibirIcone: bool;

    // 2. Construtor e Valores Iniciais Padrão
    procedimento Inicializar() {
        this.width = 200;
        this.height = 90;
        this.Titulo = "Vendas do Mês";
        this.Valor = "R$ 48.500,00";
        this.VariacaoPercentual = 14.8;
        this.CorDestaque = "#0078d4";
        this.ExibirIcone = true;
    }

    // 3. Setters com Notificação de Repintura (Equivalente ao Invalidate do Delphi)
    procedimento SetValor(novoValor: string) {
        this.Valor = novoValor;
        this.Invalidar(); // Dispara atualização visual imediata no canvas e no DOM
    }

    // 4. Renderização do Componente
    procedimento Renderizar() -> string {
        let corBadge = this.VariacaoPercentual >= 0.0 ? "#22c55e" : "#ef4444";
        return "<div class='vox-metric-card' style='border-left: 4px solid " + this.CorDestaque + ";'>" +
               "  <div class='title'>" + this.Titulo + "</div>" +
               "  <div class='value'>" + this.Valor + "</div>" +
               "  <div class='badge' style='color:" + corBadge + ";'>+" + str(this.VariacaoPercentual) + "%</div>" +
               "</div>";
    }
}
📌 Dica de Produtividade
Propriedades cujo nome se inicia por On (por exemplo OnClick, OnChange, OnHover) são automaticamente roteadas para a aba Events do Object Inspector do Vox Studio, permitindo vinculação rápida a rotinas de código com duplo clique.
Capítulo 3

Componentes Visuais vs. Componentes Não-Visuais

O sistema de componentes divide os elementos em duas categorias fundamentais, exatamente como na VCL e no FireDAC do Delphi:

1. Componentes Visuais (Visual Controls)

São elementos que compõem a interface visual direta com o usuário final. Possuem geometria (posição left, top e dimensões width, height), capturam eventos de mouse e toque, e herdam de vox_VisualControl ou de contêineres como vox_Panel.

  • Exemplos Nativos: vox_Button, vox_Edit, vox_DBGrid, vox_MainMenu, vox_Card, vox_Switch, vox_ProgressBar.
  • Comportamento no Web App: Renderizados como elementos ativos do layout (100% integrados à janela responsiva do sistema).

2. Componentes Não-Visuais (Non-Visual Components)

São módulos de infraestrutura, comunicação, execução em lote ou serviços. No ambiente de design (Form Designer), eles precisam de um ponto de manipulação para o desenvolvedor, sendo representados por um ícone quadrado estilizado de 38x38 pixels com etiqueta do nome do componente. No entanto, na aplicação web final gerada, eles são compilados exclusivamente como classes de serviço e não ocupam espaço na tela visual.

  • Exemplos Nativos: vox_Connection (Conexão a bancos de dados), vox_Query (Execução SQL), vox_DataSource (Ponte de dados), vox_Timer (Temporizador de eventos).
  • Comportamento no Web App: Instanciados no backend ou no worker cliente sem elemento DOM visível.
Capítulo 4

A Extensão de Projetos de Pacotes (.vdpk — Vox Design Package)

No Delphi, os componentes não são instalados individualmente como fontes soltos; eles são compilados em **pacotes de componentes (.dpk)**. A linguagem Vox adota exatamente este padrão profissional através dos arquivos com extensão **.vdpk** (*Vox Design Package*).

Estrutura Sintática de um Pacote .vdpk

Um pacote .vdpk é composto por três blocos declarativos:

  1. package NomeDoPacote; — Identificador único da biblioteca.
  2. requires ...; — Lista de dependências de runtime (ex: vox_rtl, vox_vcl).
  3. contains ...; — Lista de units e componentes incluídos no pacote.
// ==============================================================================
// Arquivo: VoxDashboardControls.vdpk
// ==============================================================================
package VoxDashboardControls;

requires
    vox_rtl,
    vox_vcl,
    vox_designer;

contains
    vox_RatingStars in 'vox_RatingStars.vox',
    vox_CardMetrica in 'vox_CardMetrica.vox';

// Implementação dos componentes e procedimento de registro
procedimento Register() {
    RegisterComponents("Dashboard", [
        vox_RatingStars,
        vox_CardMetrica
    ]);
}
🚀 Instalador Integrado na IDE
Para instalar um pacote .vdpk no Vox Studio, abra o menu Component ➔ 📦 Instalar Pacote de Componentes (.vdpk)..., cole o código ou clique em ✨ Carregar Modelo Oficial e pressione Compilar e Instalar na Palette. O componente ficará disponível imediatamente na Tool Palette da IDE.
Capítulo 5

O Procedimento Oficial Register() e a Tool Palette

A convenção oficial de registro de componentes do Delphi exige a declaração de um procedimento global chamado Register. Quando a IDE carrega um pacote, ela busca e executa essa rotina, passando os componentes para a paleta de ferramentas.

Assinatura da Função RegisterComponents

procedimento RegisterComponents(categoria: string, componentes: lista);

Onde:

  • categoria: Nome do grupo na Tool Palette onde os componentes residirão (ex: "Standard", "Additional", "Data Controls", "Custom", "Dashboard"). Se a categoria não existir, a IDE a cria automaticamente.
  • componentes: Vetor contendo os tipos/classes dos componentes a serem adicionados à paleta.
// Exemplo de Registro de Múltiplos Componentes
procedimento Register() {
    // Registra controles adicionais
    RegisterComponents("Additional", [
        vox_Badge,
        vox_Switch
    ]);

    // Registra controles próprios na categoria da sua empresa
    RegisterComponents("MinhaEmpresa", [
        vox_RatingStars,
        vox_CardMetrica
    ]);
}
Capítulo 6

Ciclo de Vida, Persistência e Streaming (.vxf / .dfm)

Quando um desenvolvedor arrasta um componente da paleta para o canvas da IDE e altera propriedades no Object Inspector, como a IDE armazena essas alterações sem perder os dados entre as sessões?

No Delphi, isso é resolvido pelo **Streaming VCL / .dfm**. No Vox Studio, utilizamos o formato padronizado **.vxf** (*Vox Visual Form*).

Estrutura de Streaming .vxf

O arquivo .vxf é um manifesto estruturado que registra cada componente, sua geometria e o delta de propriedades modificadas em relação aos valores padrão da classe:

Capítulo 7

Construindo Controles Data-Aware (Acesso a Dados com vox_DataSource)

O grande diferencial que consagrou o Delphi nos sistemas de gestão empresarial (ERP) foi o ecossistema de componentes **Data-Aware**: controles de interface que se vinculam diretamente a um TDataSource e respondem automaticamente às alterações do ponteiro do dataset.

A Tríade de Dados do Vox

Componente Responsabilidade Propriedades Chave
vox_Connection Estabelece a conexão física com o banco de dados (Firebird, MySQL, PostgreSQL, SQLite). Driver, Server, Port, Database, VendorLib
vox_Query Executa instruções SQL (SELECT, INSERT, UPDATE, DELETE) e retém o buffer de registros em memória. Connection, SQL, Active
vox_DataSource Atua como mediador entre o dataset (vox_Query) e os controles visuais (vox_DBGrid, vox_DBEdit). DataSet, AutoEdit

Construindo um Componente Data-Aware Customizado

Para tornar um componente Data-Aware, você deve publicar as propriedades DataSource e DataField: 

classe vox_DBRatingStars herda vox_RatingStars {
    pub let mut DataSource: string;
    pub let mut DataField: string;

    procedimento AtualizarDoDataset(valorCampo: f32) {
        this.SetRating(valorCampo);
    }
}
Capítulo 8

Projetos Práticos Passo a Passo: Criando o vox_RatingStars e vox_KanbanBoard

Neste capítulo final, implementaremos dois componentes completos prontos para uso em produção.

Projeto 1: vox_RatingStars (Avaliação por Estrelas)

classe vox_RatingStars herda vox_Panel {
    pub let mut StarsCount: i32;
    pub let mut Rating: f32;
    pub let mut ActiveColor: string;
    pub let mut InactiveColor: string;
    pub let mut ReadOnly: bool;

    procedimento Inicializar() {
        this.width = 140;
        this.height = 32;
        this.StarsCount = 5;
        this.Rating = 4.0;
        this.ActiveColor = "#ffca28";
        this.InactiveColor = "#4b5563";
        this.ReadOnly = false;
    }

    procedimento SetRating(novoValor: f32) {
        if novoValor >= 0.0 && novoValor <= f32(this.StarsCount) {
            this.Rating = novoValor;
            this.Invalidar();
        }
    }

    procedimento Renderizar() -> string {
        let estrelas = "";
        let arredondado = i32(this.Rating);
        para i de 1 ate this.StarsCount {
            if i <= arredondado {
                estrelas = estrelas + "<span style='color:" + this.ActiveColor + "; cursor:pointer;'>★</span> ";
            } senao {
                estrelas = estrelas + "<span style='color:" + this.InactiveColor + "; cursor:pointer;'>☆</span> ";
            }
        }
        return "<div class='vcl-rating-container' style='font-size: 18px;'>" + estrelas + "</div>";
    }
}

Projeto 2: vox_KanbanBoard (Quadro Kanban com Colunas e Cartões)

classe vox_KanbanBoard herda vox_Panel {
    pub let mut Colunas: string;
    pub let mut CorCabecalho: string;

    procedimento Inicializar() {
        this.width = 720;
        this.height = 420;
        this.Colunas = "A Fazer, Em Andamento, Concluído";
        this.CorCabecalho = "#1e293b";
    }

    procedimento Renderizar() -> string {
        let cols = this.Colunas.split(",");
        let html = "<div class='kanban-board' style='display:flex; gap:12px; height:100%; width:100%;'>";
        para col em cols {
            html = html + "<div class='kanban-column' style='flex:1; background:#181e29; border-radius:6px; padding:10px;'>" +
                          "  <div style='font-weight:700; color:#38bdf8; margin-bottom:8px;'>" + col.trim() + "</div>" +
                          "  <div class='kanban-card' style='background:#232b3b; padding:8px; border-radius:4px; font-size:12px; margin-bottom:6px;'>Tarefa Exemplo</div>" +
                          "</div>";
        }
        html = html + "</div>";
        return html;
    }
}

// Procedimento de Registro Final
procedimento Register() {
    RegisterComponents("Custom", [
        vox_RatingStars,
        vox_KanbanBoard
    ]);
}
